# Sources and verification

This project reconstructs selected MiXCR 3.0.13 algorithms in Python and NumPy. Its runtime uses bundled reference metadata and Python implementations of alignment, clone assembly, partial-read assembly and supported contig operations. Development tools used the original Java artifact to export reference metadata and obtain independent expected results.

The source baseline is the official [MiXCR v3.0.13 tag](https://github.com/milaboratory/mixcr/tree/v3.0.13), commit `045e9afdb83f99a7c39b2e75807736c4632aa344`. The verified original JAR identifies its build as commit `f61422609eb4743e1e55ad3fb12ab51e34952b62`. Comparison of those revisions found changes to release notes and the Maven project version; their main Java algorithm sources agree. The reconstruction used both the versioned sources and behavior measured from the shipped JAR.

The original artifact's SHA-256 is:

```text
1526a6d36221e86b775e39831b5ebaab6d5877639212c672bef2049a3fd37149
```

The associated sequence algorithms come from MiLib 1.13. RepSeq.IO 1.3.4 provides the original reference representation, and `repseqio.v1.6` identifies the bundled human reference library. These two RepSeq version labels identify different components. Exported VRegionWithP and VGeneWithP reference files preserve the corresponding alignment coordinates, gene identities, feature points and feature intersections. The Python WELL19937c generator follows Apache Commons Math so that input-dependent random sampling agrees with the original alignment procedure.

## What each verification mode establishes

The ordinary Python test suite reads saved oracle fixtures alongside algorithm-level checks. Oracle fixtures contain expected outputs previously generated by the original JAR. Running those tests checks reproducibility against that saved evidence and requires Python, NumPy and the pytest test runner. A passing saved-fixture test does not execute the original software afresh.

The optional [example comparator](../scripts/compare_example.py) runs a new original-versus-Python experiment. Supply a lawfully obtained JAR with the exact hash above and a Java executable; the script uses the current Python interpreter. From the repository root:

```sh
python scripts/compare_example.py --jar /path/to/mixcr-3.0.13.jar --java java --fastq examples/trb.fastq --output comparison-example
```

The output directory must be new. The script runs original alignment, clone assembly and TSV exports, followed by the Python analysis on the same single-end FASTQ. It records input hashes, commands, exit codes, execution logs, exported tables and `report.json`. Its default profile uses human references, VRegionWithP and CDR3 clone assembly. It checks every input read's alignment status; V/D/J/C gene identities and scores; CDR3 nucleotide sequence, amino-acid sequence and quality; clone counts and fractions; and each read's assigned clone and mapping type.

Gene-hit order is normalized, numeric text is compared numerically, and clones are matched by unique CDR3 nucleotide sequence. Clone IDs and output row order can differ while those biological values agree. Unassigned reads are compared as dropped; detailed original failure labels are outside this example's comparison fields. Inputs producing repeated CDR3 clone keys fail explicitly. Exit status is `0` for agreement, `1` for measured differences, and `2` for input or execution errors. The script enforces the artifact hash and preserves the original software's normal execution path.

This small example establishes agreement for its recorded input and declared fields. Saved fixtures cover additional modes documented elsewhere in the project. Neither form of evidence establishes compatibility with every MiXCR parameter combination, every sequencing assay, or later MiXCR releases. MiXCR 4.7 is outside this reconstruction's baseline.
