# 验证报告 — Biosoft-Project-MiXCR-Python 0.2.0

[English](validation.md) · [机器可读摘要](validation-summary.json)

六套 FASTQ 流程与 MiXCR 3.0.13 的历史对照中，所有被检字段均未发现差异。这些结果支持已列明输入、参数和输出字段的兼容性；有限样本无法证明任意输入或全部 MiXCR 功能均等价。

## 参照程序与环境

参照程序标识为 MiXCR 3.0.13，提交为 `f61422609eb4743e1e55ad3fb12ab51e34952b62`，SHA-256 为 `1526a6d36221e86b775e39831b5ebaab6d5877639212c672bef2049a3fd37149`。源码核对使用[官方 v3.0.13](https://github.com/milaboratory/mixcr/tree/v3.0.13)，固定提交为 `045e9afdb83f99a7c39b2e75807736c4632aa344`。已记录的提交比较显示差异位于 CHANGELOG 和 POM，算法源码相同。人类参考序列来自 repseqio.v1.6。

历史验证记录日期为 2026-10-12，环境为 Windows 11、Python 3.12.7、NumPy 2.4.6 和 Java 21。Python 运行期计算依赖 Python 与 NumPy。另一次独立运行审计在禁止创建子进程和访问网络的条件下，完成了 200 对 IGH 读段分析，未触发被禁止的操作。Java 用于开发期参照与验证结果生成。

## FASTQ 至克隆的完整流程

每套流程从 FASTQ 开始，覆盖比对、克隆组装、克隆导出和逐读段归属。双端输入按读段对计数。原版使用匹配参数和单线程。

| 数据 | 输入记录 | 成功比对 | 克隆数 | 比对 / 克隆 / 归属检查数 | 观察到的差异 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 合成 TRB 单端 | 1,039 条 | 1,036 | 4 | 7,252 / 36 / 2,075 | 0 |
| 合成 TRB 重叠双端 | 1,036 对 | 1,036 | 4 | 7,252 / 36 / 2,072 | 0 |
| 官方 TRB 单端 | 100 条 | 100 | 22 | 700 / 198 / 122 | 0 |
| 官方 IGH 单端 | 200 条 | 104 | 45 | 728 / 405 / 279 | 0 |
| 官方 TRB 双端，VGeneWithP | 100 对 | 99 | 22 | 693 / 198 / 122 | 0 |
| 官方 IGH 双端 | 200 对 | 169 | 86 | 1,183 / 774 / 337 | 0 |

检查数采用比较程序记录的字段检查计数，不代表独立生物样本数量。合成数据重复使用四种重排模板，覆盖反向互补、V 区替换与插缺、高低质量 CDR3 突变、CDR3 插入和无法匹配的读段。单端合成集含 17 种不同序列，重复记录用于验证丰度、映射和聚类行为。

比对检查覆盖成功或失败状态、全部保留的 V/D/J/C 基因命中及评分、CDR3 核苷酸、翻译和质量。克隆检查覆盖对应注释、计数和比例；归属检查覆盖克隆归属与映射类型。Python 比较将同分基因名称按集合处理，基础流程按 CDR3 对齐克隆。因此，基础流程检查对任意同分命中顺序，以及任意分组参数下同 CDR3 克隆的区分能力，均存在范围边界；分组功能另有专门扩展案例。历史 Java 重建版的六套导出表同时通过逐行一致性检查。

克隆计数遵循原版默认规则：被聚类吸收的读段可以获得克隆归属，同时不增加保留克隆的计数。因此，已归属读段总数与克隆计数总和具有不同含义。

## 扩展流程

七组组装案例覆盖 CDR1+CDR2+CDR3、CDR3+FR4、VDJRegion、按 V 或 V/J/C 分组，以及关闭预聚类。被检序列、质量、基因评分、计数、比例和归属均一致。三组实际 CLI 案例覆盖 FASTQ 分析、JSON 重载和 V 分组；V 分组案例准确保留十条预聚类读段标记。区域提取还通过了 1,859 组双端 IGH 区域检查与 506 组完整 VDJ 区域检查，包含 N 区间坐标。定向案例验证零长度连接区间，以及原版对序列质量和相对坐标采用不同 target 选择规则的行为。

部分读段拼接包含十组单 target 和十组双端 target 原版独立案例。三套 FASTQ 串联流程也已有记录：三读段示例得到两个克隆并保留全部来源标识；200 对 IGH 数据得到 86 个克隆且通过 951 项检查；三读段的部分拼接至 contig 流程得到两个相同 contig。合并后的加权读段计数和逐读段归属展开均经过检查。

完整 contig 命令对照覆盖合成 TRB（4 个克隆）、官方 IGH 单端（45 个克隆）和官方 IGH 双端（86 个克隆），被检字段均无差异。双端结果包含 89 条目标序列，克隆计数总和为 137。检查覆盖目标序列及质量、CDR3、计数、全部保留的 V/D/J/C 名称与评分，以及各 target 比对评分、参考和查询区间、完整 M/X/I/D 操作路径。Contig 测试夹具另覆盖 240 组位点变异、聚类与修剪案例，24 组读段到位点再到 contig 的案例，以及 12 个命令输出克隆。

其他历史 Java 独立对照包含 9,000 项随机数、哈希与模糊碱基检查，8,493 项组装映射公式检查，500 项克隆 V/J 带状比对，2,800 项多段序列兼容性检查，240 组种子映射，776 个基因延伸比对和 516 组双端合并。这些数字属于不同测试层级，不应相加解释为独立的完整流程数据集数量。

## 重跑公开回归测试

在仓库根目录安装包与测试依赖，然后执行：

```sh
python -m pip install ./python pytest pytest-subtests
python -m pytest python/tests
```

[公开测试与 JSON 参照夹具](../python/tests/)可在无需 Java 的环境运行。夹具提供测试期预期结果；运行期算法不读取这些预期结果。已保存的历史测试日志记录 **52 项测试和 2,214 个子案例通过**。这是带日期的验证结果，当前检出版本应以实际重跑结果为准。

完整历史 FASTQ 流程、原版程序、Java 重建产物、原始导出和私有命令日志未纳入公开发行。本文表格和 JSON 摘要从这些核验结果转录而来。公开夹具支持所打包案例的回归测试；完整历史流程表格仍需要额外的输入和参照产物才能重新生成。文档未将未公开证据路径列为可下载文件。

## 证据结构与解释

[validation-summary.json](validation-summary.json)记录项目和版本、参照程序身份及哈希、历史环境、六套数据计数、扩展与 contig 结果、支持配置、边界和公开夹具哈希。其中所有文件引用均相对于仓库根目录。`evidence_status` 区分历史本地流程摘要与公开回归输入。`passed` 表示该案例列明的被检字段中观察到零差异，不代表正确性的概率估计。

## 兼容范围

已验证配置覆盖导出的人类参考库、默认线性评分、V-then-J、Max 质量聚合、Opposite 双端布局，以及已列明的区域与基因分组路径。完整 CDR3 提取需要连续覆盖或成功合并。Contig 命令验证采用 CDR3 克隆和默认 contig 参数。

KAligner2、其他物种、其他双端布局、任意评分模型、复合区域、其他 contig 组装区域及自定义 subCloningRegion 仍需补充实现或验证。低质量多候选映射的同分顺序、重复序列中完整插缺路径，以及 contig 异常保留分支，尚未得到穷尽性采样。报告会标明运行时触及的已知边界。Python 使用独立 JSON 中间格式；原生 `.vdjca`、`.clns`、`.clna` 读写位于此 Python 发行范围之外。现有测试尚未建立性能、全部平台行为或临床适用性结论。
